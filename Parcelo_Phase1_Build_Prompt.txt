Parcelo Phase 1: Build Prompt

Start here: what this file is, in plain English

What it is. The long text below the line is a prompt: a detailed brief that you paste into an AI coding assistant (for example Claude Code) so it builds Phase 1 of Parcelo for you. Think of it as the written instructions you'd give a builder before they start work. You don't have to understand every technical word; the assistant does.
What Phase 1 is. The first, smallest working version of Parcelo:

& A customer signs up, enters pickup and drop-off, sees the price, and books.
& They get a tracking number.
& An admin updates the delivery status and uploads a proof-of-delivery photo.
& Anyone can type a tracking number and see where the package is.

Drivers, dispatching, stock and text messages come in later phases, so the prompt tells the assistant not to build them yet.

How to use it, step by step

1. Create an empty folder for the project and open it in your coding assistant.
2. Copy everything below the line (from "You are a senior full-stack engineer" to the end) and paste it as your first message.
3. If your assistant lets you attach files, also attach your Parcelo blueprint PDF and the Secure Coding file.
4. The assistant does step 1 and stops. Read its summary, run what it tells you to run, and check it works.
5. Type "continue to step 2" and repeat until step 11.
6. When the acceptance checks in section 11 pass, Phase 1 is done.

Tips

Don't skip the checking. The step-by-step stops are there so a mistake in step 3 doesn't get buried under steps 4 to 11.
If the assistant says something you don't understand, ask it: "explain that in simple words".
You'll need a free Firebase account. Cloud Functions need the pay-as-you-go (Blaze) plan, which requires a payment card, but the free monthly allowance normally covers a project this size.



You are a senior full-stack engineer. Build Phase 1 of Parcelo, a logistics platform, using React + Vite and a single Firebase backend. Work in small, verifiable steps, and stop for my review at the end of each numbered step in section 8.

1. What Phase 1 delivers

A customer can register, book a delivery (3 steps), see an instant price, get a tracking number and follow the package. An admin runs everything by hand from a simple dashboard. The public can look up a tracking number with no login. Phase 1 must work on its own.
Not in Phase 1 (do not build): driver app, dispatcher role UI, assignment, live location, inventory, notifications, reports, online payments.

2. Tech stack (fixed)

React + Vite, React Router, React Context for auth state, Tailwind CSS with CSS variables, lucide-react icons, Leaflet + OpenStreetMap, Nominatim for geocoding (on button press only, never per keystroke)
Firebase: Authentication (email/password), Cloud Firestore, Cloud Storage, Cloud Functions (Node.js, callable), security rules, Hosting (one site per app), App Check
Roles via Firebase custom claims: customer , admin (dispatcher and driver exist as constants only) Validation in functions with Zod; tests with Vitest and the Firebase Emulator

3. Repository structure


Each app has: index.html , vite.config.js , .env , public/ , src/{main.jsx, App.jsx, layouts/, pages/, components/, hooks/, api/} . Apps never call each other; they share the Firebase project and @parcelo/shared .

6. Business rules


& Shipment statuses: Pending -> Assigned -> In Transit -> Out for Delivery -> Delivered; Failed (from In Transit/Out for Delivery, needs a reason, can retry to Out for Delivery); Cancelled only while Pending. In Phase 1 admin moves Pending -> In Transit directly (Assigned is disabled until Phase 2). Keep the rules in one pure module
used by both shared and functions (same logic, with a test that guards they match).
& Price = (baseFee + perKm x distanceKm + perKg x weightKg) x sizeFactor, rounded to nearest N50. Test: 12 km, 3 kg, medium = N3,900. Distance = straight-line (haversine) x 1.3.
& Quote expires after 15 minutes, belongs to the caller, is single-use. Booked price never changes.
& Delivered requires a proof photo. Failed requires a reason. Customers may cancel only while Pending.
& Tracking numbers are created server-side with crypto.randomBytes , format	+ 10 characters from
 ABCDEFGHJKLMNPQRSTUVWXYZ23456789 . Use one canonical format everywhere, validate with a regex, uppercase and trim before lookup.
